# 출시 전 준비 체크리스트

현재 상태는 구현 코드 검토용이다. 아래 환경·정책·테스트 조건이 충족되기 전에는 운영 데이터 연결이나 출시 승인으로 간주하지 않는다.

## 환경 및 비밀 관리

- [ ] 별도 Supabase 개발/검증 프로젝트를 만들고 운영과 분리한다.
- [ ] 개발 환경 `.env.local`에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 설정한다. 서비스 역할 키를 브라우저/저장소에 두지 않는다.
- [ ] Supabase Auth에서 개발/운영 URL과 로그인 리다이렉트 허용 목록을 설정한다.
- [ ] Supabase 계정 생성 시 프로필 역할은 `reporter`로 시작한다. 운영자/관리자 역할 부여는 기관이 승인한 절차와 담당자로 수행한다.
- [ ] 호스팅, 도메인/TLS, 환경별 설정·비밀 관리, 배포 승인자, 롤백 책임자를 지정한다.

## 데이터베이스와 권한

- [ ] 네 migration을 검토 후 개발 DB에 순서대로 적용하고 적용 버전을 기록한다.
- [ ] 신고자 A/B, 운영 담당자, 관리자, 비활성 계정 및 가짜 자산/신고 데이터를 준비한다.
- [ ] 역할별 RLS 허용·거부를 확인한다. 본인 외 신고, 내부 메모, 비인가 프로필/자산/신고 변경을 포함한다.
- [ ] 상태 변경·감사 기록 트랜잭션, 기한/담당 변경, 중복 접수, 멱등 재요청, 동시 변경 충돌을 DB에서 검증한다.
- [ ] 백업·복구와 데이터 보존·파기 책임 및 절차를 확인한다.

## 기관 정책

- [ ] 계정 초대·회수·복구 및 내부 사용자 범위를 승인한다.
- [ ] 역할 변경 승인·감사 절차와 사용자 비활성화 정책을 승인한다.
- [ ] 우선순위 분류·의미와 처리 기한 지정 책임을 승인한다.
- [ ] SLA 임박 임계값, 시간 계산 기준, 예외 및 업무시간 처리 여부를 승인한다.
- [ ] 완료 신고 관리자 정정, 후속 신고 연결, 개인정보 보존 정책을 승인한다.

## 검증·운영 인수

- [ ] 테스트 프레임워크/CI 실행 방식을 선택하고 단위·통합·시스템 케이스를 결과 보고서에 기록한다.
- [ ] 테스트 계획서의 권한·개인정보·접근성·반응형 케이스와 모바일/키보드 흐름을 확인한다.
- [ ] 기관 업무 담당자가 역할별 인수 시나리오를 수행하고 UAT 결과를 승인한다.
- [ ] 미해결 S1/S2 결함이 없는지 확인하고 잔여 정책/결함의 승인된 제외 사항을 기록한다.
- [ ] 운영 환경 비밀값, 배포 버전, DB 마이그레이션, 백업, 롤백을 확인한 뒤 승인된 배포 절차를 따른다.

## 현재 차단 조건

- Supabase URL/키, 개발 DB, 역할별 테스트 계정이 없다.
- 계정 운영, 역할 변경, 우선순위, SLA 및 데이터 보존 정책 승인이 없다.
- 자동 테스트 러너, QA 환경, UAT 인수자가 지정되지 않았다.

이 조건은 구현 파일이 존재하는 것만으로 충족되지 않는다. 준비 완료 시 각 항목의 담당자, 날짜, 근거와 검증 결과를 함께 기록한다.
