# 서브에이전트 작업 분할 가이드

## 목적

기능을 병렬로 개선할 때 수정 파일이 겹치거나, 공통 권한·데이터 규칙이 화면별로 달라지는 일을 줄이기 위한 저장소 기준 작업 분할안이다. 현재 저장소는 Next.js App Router의 역할별 경로와 `src/lib/`, `supabase/`, 단계별 `docs/`가 이미 구분되어 있으므로 코드 폴더를 먼저 재배치하지 않는다.

## 현재 구조 확인

| 영역 | 현재 경로 | 용도 |
|---|---|---|
| 신고자 화면·동작 | `src/app/(secure)/reporter/**` | 신고 작성, 유사 신고 안내, 본인 신고 목록·상세 |
| 운영 화면·동작 | `src/app/(secure)/ops/**` | 신고 검색, 배정, 처리, 상태 변경, 상세 |
| 자산·관리자 화면 | `src/app/(secure)/assets/**`, `src/app/(secure)/admin/**` | 자산 관리, 관리자 화면 |
| 로그인·권한 공통 코드 | `src/app/login/**`, `src/app/auth/**`, `src/lib/auth/**` | 인증 흐름, 사용자 프로필·역할 |
| Supabase 공통 코드 | `src/lib/supabase/**` | 서버·브라우저 클라이언트, 환경 변수, 세션 갱신 |
| 알림 | `src/lib/notifications/**` | Slack 등 외부 알림 |
| DB 스키마·샘플 데이터 | `supabase/migrations/**`, `supabase/seed.sql` | 테이블, RLS, RPC, 초기 데이터 |
| 테스트 기준·결과 | `docs/05-테스트/**` | 테스트 계획, 케이스, 실행 보고 |
| 기획·설계·운영 문서 | `docs/00-*` ~ `docs/08-*`, `PLAN.md`, `PRD.md`, `DESIGN.md` | 요구사항부터 운영까지 기준 문서 |

현재 `package.json`에는 `test` 스크립트가 없고 저장소에 Playwright 설정 파일이나 테스트 코드가 없다. 테스트 결과 문서에는 과거 Playwright 스모크 결과가 기록되어 있으므로, QA 자동화 작업은 그 실행 설정과 재현 가능한 증거를 다시 갖추는 일부터 맡긴다. RLS·트랜잭션 검증은 브라우저 테스트와 같은 것으로 취급하지 않는다.

## 권장 작업 레인

한 번의 작업에서 모든 레인을 동시에 실행하기보다, 목표와 의존성을 보고 2~4개를 선택한다. 각 에이전트는 지정된 경로만 수정하고, 공유 경로 변경이 필요하면 통합 담당자에게 먼저 알린다.

### A. 신고자 경험 에이전트

- **담당:** `src/app/(secure)/reporter/**`
- **예시:** 신고 작성 UX, 유사 신고 후 입력값 유지, 내 신고 목록·상세, 신고자 모바일 사용성.
- **완료 기준:** 신고자 시나리오와 오류·빈 상태가 분명하고, 변경한 UI를 실제 브라우저 또는 명령으로 확인한다.
- **제외:** 공통 인증, DB 정책, 운영자 화면.

### B. 운영 처리 에이전트

- **담당:** `src/app/(secure)/ops/**`
- **예시:** 신고 목록 필터, 배정, 상태 전이, 공개 업데이트와 내부 메모, 운영자 상세 화면.
- **완료 기준:** 허용된 상태 전이와 역할별 표시를 기준 문서에 맞춰 구현하고, 변경 경로를 검증한다.
- **제외:** `src/lib/auth/**`, `supabase/migrations/**`의 독자적인 권한·스키마 변경.

### C. 데이터·보안 에이전트

- **담당:** `supabase/migrations/**`, `supabase/seed.sql`, `src/lib/supabase/**`, `src/lib/auth/**`
- **예시:** RLS 검증, RPC·제약·트랜잭션, 인증 권한 경계, 마이그레이션 이력 정합성.
- **완료 기준:** 변경 이유, 영향받는 역할, 적용·롤백 조건을 기록한다. 실제 DB 적용은 환경을 확인하고 승인된 절차로 진행한다.
- **주의:** 서비스 역할 키나 `.env.local` 값을 읽어 프롬프트·문서·커밋에 넣지 않는다. 정책이 미정이면 임의로 확정하지 않고 차단 사항으로 보고한다.

### D. QA·테스트 자동화 에이전트

- **담당:** `tests/**`, Playwright 설정 파일, `package.json` 및 잠금 파일의 테스트 관련 변경, `docs/05-테스트/**`
- **예시:** `tests/e2e/`에 로그인·보호 경로·신고·유사 신고 입력값 유지 테스트 추가, 실패 재현, 결과 보고서 갱신.
- **완료 기준:** 한 명이 새 체크아웃에서 실행할 수 있는 명령과 필요한 환경 변수를 문서화한다. 실행하지 않은 케이스를 통과로 표시하지 않는다.
- **주의:** 테스트 계정과 운영 계정을 분리하고, RLS를 검증할 때 브라우저 UI 통과만으로 권한 통과를 선언하지 않는다.

### E. 문서·CI·배포 준비 에이전트

- **담당:** `.github/workflows/**`(추가 시), `README.md`, `docs/06-배포/**`, `docs/07-유지보수/**` 및 담당자와 합의한 문서 파일.
- **예시:** CI에서 lint/typecheck/build 실행, 배포 체크리스트, 환경 재현 절차, 장애 대응 문서.
- **완료 기준:** 비밀값을 추가하지 않고, 모든 명령과 배포 상태를 재현 가능한 근거에 맞춰 기록한다.
- **제외:** 승인 없이 Production 환경 변수·사용자·데이터를 변경하거나 배포하지 않는다.

## 순서와 병렬화 기준

1. **통합 담당자:** 작업 목표, 완료 조건, 미확정 업무 정책, 파일 소유권을 정한다.
2. **데이터·보안 레인:** UI가 의존하는 권한·데이터 계약이 바뀌면 먼저 계약과 마이그레이션 초안을 검토한다.
3. **신고자·운영 레인:** 서로 다른 라우트 경로 안에서 병렬 작업할 수 있다. 공통 레이아웃이나 DB 계약이 필요하면 먼저 조율한다.
4. **QA 레인:** 변경 계약을 확인한 후 독립적인 검증과 회귀 테스트를 만든다. 테스트 기반 구축은 별도 선행 작업으로 맡길 수 있다.
5. **문서·CI 레인:** 최종 명령, 환경 조건, 실제 검증 결과를 반영한다.
6. **통합 담당자:** 각 결과를 검토·병합하고 전체 회귀 확인 후에만 배포한다.

서로 다른 에이전트가 같은 체크아웃에서 동시에 파일을 수정하지 않는다. 병렬 구현은 별도 브랜치/워크트리를 사용한다. 파일을 공유하는 경우 한 에이전트만 소유자로 두고 나머지는 제안만 전달한다.

## 공유 파일 소유권

다음 파일·경로는 작업 레인 간 충돌 가능성이 높으므로 통합 담당자가 소유자를 지정한다.

- `src/app/(secure)/layout.tsx`, `src/app/globals.css`: 공통 UI·보호 레이아웃.
- `src/lib/**`: 여러 화면이 쓰는 인증, Supabase, 알림 코드.
- `supabase/migrations/**`: 스키마 순서·RLS·RPC 계약.
- `package.json`, `package-lock.json`: 테스트·도구 의존성 변경.
- `docs/05-테스트/테스트결과보고서.md`: QA 결과 기록 단일 작성자.
- `PLAN.md`, PRD/SRS/정책·설계 문서: 기준 문서 담당자 승인 없이 요구사항을 고치지 않는다.

## 에이전트에게 매번 전달할 작업 형식

```text
목표: [사용자에게 보이는 결과]
담당 경로: [수정 허용 경로]
수정 금지: [공유 파일, 비밀값, 운영 환경 등]
기준 문서: [요구사항/정책/테스트 케이스]
완료 조건: [확인 가능한 항목]
검증: [실행할 명령 또는 수동 확인 단계]
보고: 수정 파일, 결정/가정, 실행 명령과 결과, 미해결 위험
```

각 에이전트에게 별도 저장소 세부사항이 자동 전달된다고 가정하지 않는다. 작업 요청에 필요한 경로·정책·검증 조건을 직접 포함한다. 에이전트가 커밋·푸시·Production 배포를 맡지 않도록 하고 통합 담당자가 최종 변경을 검토한다.
