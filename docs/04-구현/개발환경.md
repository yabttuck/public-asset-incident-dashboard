# 로컬 개발 환경

## 요구 환경

- Node.js 20.9 이상 (현재 확인된 개발 환경: Node.js 22.13.1)
- npm 10 이상
- 개발 Supabase 프로젝트 `public-asset-incident-dashboard-dev`를 준비했습니다. 실제 인증·데이터 연결에는 `.env.local`이 필요합니다.

현재 Next.js 16 기본 Turbopack 빌드는 이 Windows 실행 환경에서 CSS 로더 하위 프로세스 생성 중 종료됩니다. 개발 및 production build 스크립트는 현재 통과한 Webpack 경로를 사용합니다. 환경이 바뀌면 Turbopack 전환을 다시 검토할 수 있습니다.

## 설치와 실행

저장소 루트에서 아래 명령을 실행합니다.

```powershell
npm ci
npm run dev
```

개발 서버가 안내하는 로컬 주소를 브라우저에서 엽니다. 기본 포트는 3000입니다.

## 검토 명령

```powershell
npm run lint
npm run typecheck
npm run build
```

## 환경 변수

`.env.example`을 참고해 로컬 전용 `.env.local`을 준비했습니다. Supabase URL과 publishable key를 사용하며 `.env.local`은 Git에서 제외됩니다. `service_role`/secret 키는 브라우저나 저장소에 넣지 않습니다.

네 개 마이그레이션은 2026-11-26 Supabase Dashboard SQL Editor에서 개발 프로젝트에 적용했습니다. `profiles`, `assets`, `incidents`, `incident_updates`, `incident_audit_logs` 테이블 존재를 확인했습니다. 이 적용은 Supabase CLI 이력에 기록되지 않았으므로 다음 마이그레이션 자동화 전에 적용 이력을 정합화해야 합니다. 새 Auth 사용자는 프로필 트리거로 `reporter` 역할을 기본 부여합니다. 운영 담당자·관리자 역할은 개발 프로젝트에서만 승인된 테스트 계정에 수동 부여하고, 운영 프로젝트에는 기관 승인 절차를 따릅니다.

## 화면 시안

`design/stitch/krds_*/code.html`은 별도로 열어 보는 정적 화면입니다. 앱 코드와 데이터 연동을 마친 것으로 간주하지 않습니다.
