## 목차
1. 검토 개요
2. 설계 휴리스틱 검토
3. 접근성 및 반응형 검토
4. 사용자 흐름·오류 상태 검토
5. 결과와 후속 조치

## 1. UX 검토 개요

| 항목 | 내용 |
|---|---|
| 대상 | DESIGN.md 및 02-시스템설계 화면설계서 |
| 버전 | 0.1 / 설계 기반 사전 검토 |
| 방법 | 문서 검토 |
| 상태 | 실제 화면·사용자 평가 미실시 |

이 검토는 구현 화면이 아니라 문서에 명시된 UX 의도에 대한 사전 검토다. 관찰된 사용성 성과나 WCAG 적합성을 의미하지 않는다.

## 2. 휴리스틱 검토

척도: 양호(설계에서 고려됨), 보완 필요(추가 명세 필요), 평가 불가(실물 화면 필요).

| 원칙 | 판단 | 근거·후속 |
|---|---|---|
| 시스템 상태 가시성 | 양호 | 로딩·저장·오류·빈 상태를 구분하도록 설계 |
| 실제 업무 용어 사용 | 보완 필요 | 기관별 자산명·우선순위·상태 표현 검토 |
| 사용자 통제와 복구 | 보완 필요 | 유사 신고 취소, 오류 재시도 및 입력 보존을 구현 화면에서 확인 |
| 일관성과 표준 | 양호 | DESIGN.md의 토큰과 공통 배지·표 원칙 참조 |
| 오류 예방 | 양호 | 필수값 검증, 완료 요약, 재전송 방지 요구 |
| 회상보다 인식 | 보완 필요 | 필터 상태와 검색 기준이 화면에서 보이는지 프로토타입 점검 |
| 유연성과 효율 | 평가 불가 | 실제 운영자 사용성과 표 조작 확인 필요 |
| 최소한의 디자인 | 양호 | 대응·SLA 우선순위 중심 구조 |
| 오류 진단·복구 | 보완 필요 | 사용자 메시지와 재시도 문구 프로토타입 검토 |
| 도움말 | 평가 불가 | 화면 도움말 범위는 미설계 |

## 3. 접근성·반응형 사전 점검

| 항목 | 문서 설계 상태 | 구현 검토 시 확인 |
|---|---|---|
| 텍스트 라벨·오류 연결 | 요구됨 | 폼 레이블과 보조기술 안내 |
| 키보드·포커스 | 요구됨 | 모든 주요 동작의 키보드 순서와 포커스 가시성 |
| 색상 외 상태 표현 | 요구됨 | 상태 텍스트·아이콘과 대비 |
| 반응형 모바일 흐름 | 요구됨 | 신고·본인 조회·핵심 운영정보 사용 |
| 표의 작은 화면 대응 | 권장 | 가로 넘침 및 우선 정보 표현 |
| 다이얼로그 포커스 | 세부 미정 | 포커스 진입·복귀·닫기 동작 |

브레이크포인트와 WCAG 준수 목표는 구현 및 기준 승인 후 정한다. 현재 적합성 판정은 하지 않는다.

## 4. 주요 사용자 흐름 검토

### 신고 접수
필수 입력 → 자산·위치 → 유사 건 안내 → 계속 접수/취소 → ID 확인 흐름이다. 안내가 접수 차단처럼 보이지 않도록 문구를 사용자에게 검토받아야 한다.

### 운영 처리
미처리 확인 → 신고 상세 → 담당자·우선순위·기한 설정 → 조치 기록 → 완료 요약 입력 → 완료 확인 흐름이다. 내부 메모와 신고자 공개 업데이트의 차이를 작성 시 명확히 표시할 필요가 있다.

### 오류·빈 상태
네트워크 실패 시 입력 유지, 검색 결과 없음, 데이터 없음, 접근 권한 없음, 동시 상태 변경을 별도 화면으로 제시한다. 사용자 메시지에 다른 사람의 신고 존재 여부나 내부 메모를 유출하지 않는지 검토한다.

## 5. 결과 및 후속 조치

| 우선순위 | 발견/권고 | 후속 검증 |
|---|---|---|
| 높음 | 실제 사용자 역할·용어와 업무 흐름을 확인할 증거가 아직 없음 | 신고자·운영자 인터뷰 및 프로토타입 리뷰 |
| 높음 | 권한별 화면이 실제로 민감 데이터를 감추는지 평가 불가 | 역할 계정으로 UI와 네트워크 응답 점검 |
| 중간 | 유사 신고 안내와 오류 문구는 개념 수준 | 문구 리뷰 및 사용성 관찰 |
| 중간 | 모바일 표와 대화상자 상세 동작 미정 | 반응형 구현 후 기기별 키보드·터치 점검 |

승인 및 참여자 정보는 실제 검토 후 기록한다. 본 문서는 디자인 단계 사전 리뷰이며 최종 UX 승인본이 아니다.
