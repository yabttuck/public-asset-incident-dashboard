# 단계별 검토 체크리스트 (Phase Review Checklist)

## 단계별 검토 현황

| 단계 | 산출물 | 검토 상태 | 게이트 판단 |
|---|---|---|---|
| G0 기획 | PRD, DESIGN, 00-기획 문서 | 초안 작성, 승인자 미정 | 미승인 |
| G1 요구사항 | SRS, RTM, 유스케이스 | 초안 작성, 정책 미결정 | 미승인 |
| G2 시스템 설계 | SAD, DB/API/화면 설계 | 초안 작성, 구현 검증 전 | 미승인 |
| G3 상세 설계 | 상세설계서 | 초안 작성 | 미승인 |
| G4 구현·테스트 인계 | 구현-테스트-인계서 | 앱 미구현, QA 환경 없음 | 진입 불가 |
| G5 테스트 | 계획·케이스·결과 | 문서 작성, 테스트 미실행 | 미통과 |
| G6 배포·운영 | 배포·운영 문서 | 초안, 배포 환경 없음 | 진입 불가 |

문서가 존재한다는 사실은 승인이나 검증 완료를 의미하지 않는다.

## 공통 승인 기록

| 게이트 | 판단 | 승인자·일시 | 근거·후속 |
|---|---|---|---|
| G0–G3 | 검토 요청 전 / 미승인 | 미정 | 이해관계자 검토·정책 확정 필요 |
| G4–G6 | 보류 | 미정 | 앱 구현, QA 검증 및 운영 환경 필요 |

## G0 기획 검토
- [x] 제품 목표, 사용자 역할, MVP 및 범위 밖 항목 문서화
- [x] 사용자 문제와 성과 지표를 검증 전 가설로 구분
- [ ] 기관 사용자·운영 담당자 인터뷰 및 업무 흐름 확인
- [ ] 기관별 SLA·계정·분류 정책 승인
- [ ] 문서 승인자 지정

## G1 요구사항 검토
- [x] 요구사항 ID와 우선순위 정의
- [x] 정책·유스케이스·검증 시나리오를 RTM에 연결
- [x] 완료 조건, 권한, 감사 기록, SLA의 주요 예외 포함
- [ ] 모든 기관별 정책과 계정 운영 방식 확정
- [ ] 요구사항 소유자·검토자 승인

## G2 시스템 설계 검토
- [x] 웹 앱·Supabase 예정 구성 및 경계 문서화
- [x] 데이터 모델, RLS, 트랜잭션, 핵심 화면·논리 API 설계
- [ ] 구현 기술 버전·배포 환경 확정
- [ ] DB 함수/RPC와 역할별 RLS 정책 상세 검증
- [ ] 백업·복구·성능·가용성 기준 승인

## G3 상세 설계 검토
- [x] 신고 도메인, 상태 전이, SLA 판정과 주요 처리 시퀀스 정의
- [x] 오류·동시 변경·감사 이력 조건 명시
- [ ] 구현 구조와 상세 설계 간 일치 검토
- [ ] 운영·보안 검토자 승인

## G4 구현 검토 및 QA 인계
- [ ] 소스 코드·빌드 식별자와 요구사항 구현 위치 기록
- [ ] 코드 리뷰, 빌드, 단위·통합 테스트 결과 확보
- [ ] QA 환경, 테스트 계정, 가짜 데이터 준비
- [ ] 미해결 결함과 제약을 인수자에게 전달
- **현재 판단:** 앱 코드 및 환경이 없어 인계 불가

## G5 테스트 검토
- [x] 테스트 계획과 요구사항 기반 케이스 작성
- [ ] 구현 대상 P0 케이스 실행 및 결과·증빙 기록
- [ ] 권한/RLS, 감사 원자성, 동시성 검증 통과
- [ ] S1/S2 미해결 결함 해소 또는 승인된 조치
- [ ] UAT 및 종료 기준 승인
- **현재 판단:** 실행 테스트 0건, 출시 종료 기준 미충족

## G6 배포·운영 검토
- [x] 배포·롤백 및 운영 준비 문서 초안 작성
- [ ] 검증된 릴리스, 백업/복구 및 롤백 절차 확인
- [ ] 운영 담당자, 모니터링·연락망, 데이터 보존 기준 지정
- [ ] 개인정보·보안·기관 정책 승인
- **현재 판단:** 배포 환경이 없어 운영 인수 불가

- 대상 문서 버전 또는 커밋
- 항목 ID / 발견 사항 / 근거 / 심각도
- 조치 담당자 / 목표일 / 반영 위치
- 재검토 결과 / 승인 또는 보류 판단
