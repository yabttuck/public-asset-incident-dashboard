# 프로젝트 관리 산출물 (Project Management Artifacts)

## 1. WBS 및 일정

일정·담당자·예산이 제공되지 않아 날짜를 임의로 정하지 않는다. 아래 순서는 워터폴 의존 관계이며, 각 단계의 승인 후 다음 단계로 이동한다.

| WBS | 작업 | 산출물 | 선행 조건 | 상태 |
|---|---|---|---|---|
| 0 | 제품 기획 | PRD, DESIGN, 00-기획 | 없음 | 초안 작성 |
| 1 | 요구사항 분석 | SRS, RTM, 유스케이스 | G0 검토 | 초안 작성 |
| 2 | 시스템 설계 | SAD, DB/API/화면 설계 | G1 승인 | 초안 작성 |
| 3 | 상세 설계 | 상세설계서 | G2 승인 | 초안 작성 |
| 4 | 구현 | 앱 코드, 마이그레이션 | G3 승인·정책 결정 | 미착수 |
| 5 | 테스트 | 실행 증빙·결과 보고 | 구현 완료·QA 환경 | 미착수 |
| 6 | 배포·인수 | 릴리스·운영 인수 | G5 통과·운영 승인 | 미착수 |
| 7 | 유지보수 | 변경·운영 기록 | G6 인수 | 미착수 |
| 8 | 검토·종료 | 게이트 검토·완료 보고 | 단계 산출물 | 진행 중 |

## 2. 위험 관리 대장

평가는 초기 정성 평가다. 확률·영향 점수의 공식 척도는 조직 승인 전 사용하지 않는다.

| ID | 위험 | 가능 영향 | 대응 | 상태 |
|---|---|---|---|---|
| R-01 | 기관별 SLA 및 우선순위 미확정 | 잘못된 임박 표시·업무 기대 불일치 | 운영 책임자 승인 후 설정·경계 테스트 | 열림 |
| R-02 | 계정 발급·역할 정책 미확정 | 계정 생성 및 접근 통제 지연 | 기관 인증 담당과 역할·회수 흐름 결정 | 열림 |
| R-03 | RLS 또는 감사 트랜잭션 오류 | 개인정보 노출 또는 이력 신뢰성 저하 | 역할별 부정 테스트·실패 주입 | 열림 |
| R-04 | 실제 사용자 데이터가 테스트로 유입 | 개인정보 노출 | 가짜 테스트 데이터만 사용, 접근 분리 | 관리 필요 |
| R-05 | 프로젝트 코드·배포 환경 미구성 | 검증·일정 추정 불가 | 구현 기준선과 환경을 별도 계획 | 열림 |
| R-06 | 백업·복구 조건 미정 | 데이터 복구 지연·손실 위험 | 요금제·기관 보존 기준 확인 후 복구 연습 | 열림 |
| R-07 | 화면 요구가 기관 용어와 다를 수 있음 | 채택성 저하·재작업 | 담당자 인터뷰 및 프로토타입 검토 | 열림 |

## 3. 커뮤니케이션 계획

| 대상 | 공유 내용 | 주기 | 책임 |
|---|---|---|---|
| 프로젝트 작성자/개발자 | 진행, 변경, 테스트와 차단 항목 | 작업일별 | 담당자 지정 필요 |
| 업무 운영 담당자 | 정책 질문, 사용자 흐름, UAT | 단계별 검토 시 | 기관 담당자 미정 |
| QA 인수자 | 빌드·환경·케이스·결함 | G4/G5 및 변경 시 | 인수자 미정 |
| 보안·개인정보 담당 | RLS, 데이터, 보존, 배포 위험 | 설계·배포 전 | 담당자 미정 |

회의 및 에스컬레이션 채널은 조직에서 지정한다. 보안 사고나 개인정보 노출 우려는 일반 진행 보고보다 우선해 지정된 보안 대응 경로로 보고한다.

## 4. 변경 관리
변경 요청은 [유지보수계획서](../07-유지보수/유지보수계획서.md)의 CR 양식을 따른다. 승인 전 운영 범위에 반영하지 않는다. 승인된 변경은 요구사항 ID, 영향 문서, 테스트, 배포·롤백 기록에 연결한다.

## 5. 프로젝트 완료 보고서 양식

프로젝트 종료 시 계획 대비 실제 범위·일정, 요구사항 커버리지, 테스트·결함 결과, 사용자 검증, 배포·인수 상태, 미해결 위험, 교훈 및 잔여 과제를 작성한다. 현재 구현·사용자 검증·배포 실적은 없어 완료 보고를 작성하지 않는다.
