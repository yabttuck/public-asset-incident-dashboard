# 배포 계획서 (Deployment Plan)

## 1. 배포 개요

### 배포 정보
| 항목 | 기록 |
|---|---|
| 프로젝트 | 공공 시설물·전산 자산 장애 접수 및 관제 대시보드 |
| 문서 상태 | 초안 — 구현 및 배포 환경 미구성 |
| 릴리스 버전 | 미정 |
| 배포 일시 / 책임자 | 미정 |
| 기준 문서 | [SRS](../01-요구사항분석/요구사항명세서-SRS.md), [SAD](../02-시스템설계/시스템아키텍처설계서-SAD.md), [테스트 결과](../05-테스트/테스트결과보고서.md) |

### 범위와 전제
배포 대상은 Next.js 웹 앱과 Supabase Auth/Postgres를 예정한다. 호스팅, 도메인, CI/CD, 기관 운영망 연결은 미정이다. 현재 앱 코드와 검증된 릴리스가 없으므로 실제 배포 승인은 불가하다. 아래 절차는 향후 릴리스에 적용할 체크리스트다.

## 2. 환경 구성

| 환경 | 목적 | 데이터·접근 |
|---|---|---|
| DEV | 개발·단위/통합 검증 | 개발 Supabase, 가짜 데이터, 개발자 접근 |
| STG | QA/UAT 및 배포 후보 검증 | 운영과 분리된 Supabase 프로젝트, 역할별 테스트 계정 |
| PROD | 승인된 실제 업무 운영 | 기관 승인 데이터와 제한된 관리자 접근 |

환경별 Supabase 프로젝트·호스팅·주소는 따로 구성한다. 운영 자료를 DEV/STG로 복사하지 않는다. 서비스 역할 키는 배포 플랫폼의 비밀 설정에만 저장하고 로그나 Git에 기록하지 않는다.

### 사전 인프라 체크
- [ ] 도메인·TLS와 배포 담당자 승인
- [ ] 환경 변수 및 키의 비밀 저장 확인
- [ ] DB 백업·복구 옵션과 책임자 확인
- [ ] 운영 계정·역할·관리자 최소 인원 확인
- [ ] 개인정보·보존·기관 SLA 기준 승인
- [ ] 테스트 결과, 보안/RLS 검증, UAT 승인 확인
- [ ] 배포 및 롤백을 수행할 담당자 확보

## 3. 배포 절차

### Phase 1: 배포 준비
1. 대상 커밋 SHA와 릴리스 노트를 고정한다.
2. 변경 목록, 마이그레이션, 환경 변수, 알려진 이슈를 검토한다.
3. STG에서 핵심 P0 흐름과 권한 테스트를 통과시킨다.
4. 백업 상태와 롤백 담당자를 확인한다.

### Phase 2: 데이터베이스 마이그레이션
1. 변경 스크립트와 영향 테이블을 확인한다.
2. 운영 백업 또는 복구 수단을 확인한다.
3. 승인된 순서로 마이그레이션을 실행하고 결과를 기록한다.
4. RLS와 DB 함수 권한을 샘플 역할 계정으로 확인한다.

### Phase 3: 앱 배포 및 검증
1. 고정된 커밋에서 빌드 아티팩트를 생성한다.
2. 운영 환경 비밀값을 연결하고 애플리케이션을 배포한다.
3. 로그인, 신고 접수, 목록 조회, 상태 변경, 감사 기록, 권한 거부를 점검한다.
4. 오류·민감정보 노출 여부를 확인한 후 배포 결과를 기록한다.

### 사후 작업 및 G6 인수
배포자와 운영 인수자가 버전, 시각, 마이그레이션 결과, 스모크 테스트, 알려진 이슈, 모니터링 위치, 롤백 판단자를 기록한다. 운영 인수 승인 전까지 미완료 항목을 명시하고 임의로 완료 처리하지 않는다.

## 4. 롤백 계획

### 기준
S1 보안/데이터 노출, 핵심 신고·처리 불능, 감사 이력 손실, 심각한 데이터 불일치가 발생하면 배포 책임자가 롤백 또는 서비스 제한을 판단한다. 실제 판단 시간 기준은 운영 SLA 승인 후 정한다.

### 절차
1. 신규 변경과 배포 시각, 영향 범위를 기록하고 담당자에게 알린다.
2. 앱 변경은 직전 검증된 아티팩트로 복구한다.
3. DB 변경은 하위 호환성을 우선 설계한다. 파괴적 마이그레이션은 앱 배포와 분리해 단계화한다.
4. 무조건적인 데이터 역변환은 하지 않는다. 백업 복구는 데이터 손실 범위와 승인자를 확인한 뒤 수행한다.
5. 로그인·신고·조회·권한·감사 테스트와 데이터 정합성을 재확인한다.
6. 원인, 조치, 영향 및 후속 티켓을 기록한다.

## 5. 일정과 릴리스 기록
릴리스 일정·다운타임·관련 부서 연락 일정은 실제 운영 일정 승인 후 작성한다. 현재 계획된 배포 일시나 서비스 영향은 없다.
