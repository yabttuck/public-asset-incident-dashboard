| 액터 | 설명 |
|---|---|

### 2.3 액터 권한 계층

관리자는 운영 담당자 권한을 포함한다. 신고자 권한은 신고 생성과 본인 건 조회 범위다. 실제 서버·DB 권한이 화면 버튼 노출보다 우선한다.

## 4. 공통 규칙

- 신고 데이터 조회·변경은 인증 및 역할 확인 후 수행한다.
- 모든 시각은 저장 시 시간대 정보를 유지하고 화면에서는 한국 표준시로 표시한다.
- 실패한 저장을 성공으로 안내하지 않는다. 사용자가 재시도할 수 있도록 가능한 범위에서 입력을 유지한다.
- 상태·담당자·우선순위·기한 변경에는 행위자와 시각을 남긴다.
- 운영 상세 화면에서는 공개 업데이트와 내부 메모를 구분한다.
- 각 UC의 사전 조건을 충족하지 못하면 권한 없는 접근 또는 유효하지 않은 입력으로 처리하고 데이터를 변경하지 않는다.

## 5. 유스케이스 상세 명세

### 5.1 UC-001: 로그인·로그아웃

**주 액터:** 신고자, 운영 담당자, 관리자  
**목표:** 인증 사용자만 허용된 업무 기능을 사용하도록 세션을 시작하거나 종료한다.  
**사전 조건:** 사용자 계정이 기관의 계정 발급 절차에 따라 활성화되어 있다. 계정 발급 방식은 미결정이다.

**기본 흐름**
1. 사용자가 로그인 화면을 연다.
2. 인증 정보를 입력하고 로그인을 요청한다.
3. 인증 서비스가 자격을 확인하고 시스템이 사용자 역할을 확인한다.
4. 시스템은 역할에 맞는 시작 화면으로 이동시킨다.
5. 로그아웃 요청 시 세션을 종료하고 로그인 화면으로 이동시킨다.

**대안 흐름**
- 역할이 비활성 또는 미지정이면 보호된 기능 접근을 거부하고 안내한다.
- 로그인 상태에서 보호된 URL을 열면 권한을 확인한 뒤 허용된 화면을 표시한다.

**예외 흐름**
- 인증 실패 또는 서비스 오류 시 세션을 만들지 않고 일반적인 오류 안내를 표시한다.
- 세션 만료 시 보호된 요청을 거부하고 다시 인증하도록 안내한다.

**사후 조건:** 성공한 로그인은 역할이 연결된 세션을 갖고, 로그아웃 후 보호 데이터에 접근할 수 없다.  
**관련 규칙:** BP-AUTH-001, BP-AUTH-002  
**화면 참조:** 로그인  
**관련 요구사항:** FR-001, FR-002; NFR-001

### 5.2 UC-002: 장애 신고 접수

**주 액터:** 신고자  
**목표:** 자산 또는 위치의 장애를 표준 정보와 함께 등록한다.  
**사전 조건:** 신고자가 로그인했다.

**기본 흐름**
1. 신고자가 신고 작성 화면을 연다.
2. 자산을 선택하거나 위치를 입력하고 제목, 상세 증상, 우선순위, 발생 시각을 입력한다.
3. 시스템은 필수값과 입력 형식을 확인한다.
4. 같은 자산의 미해결 신고가 있으면 유사 신고 안내와 확인 가능한 기존 건을 표시한다.
5. 신고자가 별도 신고로 계속 진행한다.
6. 시스템은 접수 ID, 신고자, 접수 시각, ‘접수’ 상태를 생성해 저장한다.
7. 시스템은 접수 ID와 상태를 보여준다.

**대안 흐름**
- 유사 건 안내에서 취소하면 작성 화면으로 돌아가거나 종료한다. 이미 존재하는 신고에 자동으로 병합하지 않는다.
- 자산 목록에 없는 위치는 원문 위치를 기록해 신고를 허용한다.

**예외 흐름**
- 필수값이 없거나 형식이 잘못되면 해당 입력을 표시하고 저장하지 않는다.
- 저장 실패 시 성공으로 안내하지 않고 입력값을 유지해 재시도할 수 있게 한다.
- 동시에 중복 제출된 요청은 이중 생성이 되지 않도록 서버 측 검증을 적용한다.

**사후 조건:** 성공 시 신고가 ‘접수’ 상태로 존재하며 신고자는 해당 건을 조회할 수 있다.  
**관련 규칙:** BP-INC-001, BP-INC-002, BP-ERR-001  
**화면 참조:** 신고 작성  
**관련 요구사항:** FR-003, FR-004, FR-005; NFR-002, NFR-007

### 5.3 UC-003: 본인 신고 조회

**주 액터:** 신고자  
**목표:** 제출한 신고와 공개된 진행 상황을 확인한다.  
**사전 조건:** 신고자가 로그인했다.

**기본 흐름**
1. 신고자가 본인 신고 목록을 연다.
2. 시스템은 해당 사용자가 제출한 신고만 표시한다.
3. 신고자가 한 건을 선택한다.
4. 시스템은 상태, 자산/위치, 기한 공개 범위, 공개 조치 업데이트를 표시한다.

**대안 흐름**
- 결과가 없으면 아직 신고가 없음을 안내하고 신규 신고 경로를 제공한다.
- 검색·기간 필터가 적용되면 본인 데이터 범위에서만 결과를 좁힌다.

**예외 흐름**
- 다른 사용자의 신고 ID로 접근하면 데이터를 반환하지 않는다.
- 내부 메모나 권한 제한 자료를 요청해도 내용을 반환하지 않는다.

**사후 조건:** 신고자는 본인 건의 공개 정보만 확인한다.  
**관련 규칙:** BP-PRIV-001, BP-AUTH-003  
**화면 참조:** 내 신고 목록, 신고 상세  
**관련 요구사항:** FR-002, FR-006; NFR-001, NFR-002

### 5.4 UC-004: 운영 대시보드·신고 목록 조회

**주 액터:** 운영 담당자, 관리자  
**목표:** 처리 책임과 SLA 위험을 확인하고 대상 신고를 찾는다.  
**사전 조건:** 운영 권한으로 인증되어 있다.

**기본 흐름**
1. 액터가 대시보드를 연다.
2. 시스템은 전체, 미처리, SLA 임박, 완료 요약을 권한 범위 내 데이터로 계산한다.
3. 최근 신고 테이블에 식별 정보, 상태, 우선순위, 담당자, 기한, 최근 변경을 표시한다.
4. 액터가 상태·우선순위·자산/위치·기간 조건을 적용하거나 검색·정렬한다.
5. 액터가 신고를 선택해 상세 처리 화면으로 이동한다.

**대안 흐름**
- 기한 없는 건은 임박·초과로 계산하지 않고 별도 식별한다.
- 데이터가 없거나 필터 결과가 없으면 빈 상태를 표시한다.

**예외 흐름**
- 로딩 또는 조회 실패 시 지표를 정상 데이터처럼 표시하지 않고 오류와 재시도 경로를 제공한다.
- 완료 신고는 미완료 SLA 초과 건수에서 제외한다.

**사후 조건:** 조회 조건과 계산 결과가 표시된다.  
**관련 규칙:** BP-SLA-001, BP-SLA-002, BP-STAT-001, BP-STAT-002  
**화면 참조:** 운영 대시보드, 신고 목록  
**관련 요구사항:** FR-002, FR-006, FR-011; NFR-005, NFR-006, NFR-007

### 5.5 UC-005: 신고 분류·배정

**주 액터:** 운영 담당자  
**목표:** 신고의 우선 대응 수준과 책임자, 처리 기한을 지정한다.  
**사전 조건:** 운영 권한이 있고 대상 신고가 존재한다.

**기본 흐름**
1. 담당자가 신고 상세를 연다.
2. 현재 자산·증상과 기존 처리 이력을 검토한다.
3. 담당자, 우선순위 및 처리 기한을 입력하거나 변경한다.
4. 시스템은 권한과 값의 유효성을 확인한다.
5. 변경 내용과 행위자·시각을 감사 이력에 저장한다.
6. 성공 결과와 갱신된 신고 정보를 표시한다.

**대안 흐름**
- 관리자는 운영 담당자와 동일한 배정 작업을 수행할 수 있다.
- 기관 분류 기준이 아직 구성되지 않은 경우 구현된 허용 값만 제공하고 미정 값을 임의로 생성하지 않는다.

**예외 흐름**
- 저장 시 다른 담당자가 먼저 변경했다면 최신 값을 다시 보여주고 확인을 요청한다.
- 감사 이력 저장이 실패하면 신고 변경도 반영하지 않는다.

**사후 조건:** 변경사항과 감사 기록이 함께 존재하거나 둘 다 반영되지 않는다.  
**관련 규칙:** BP-OPS-001, BP-SLA-001, BP-ERR-002, BP-AUDIT-001  
**화면 참조:** 신고 상세·배정  
**관련 요구사항:** FR-007, FR-010; NFR-003, NFR-004

### 5.6 UC-006: 조치 기록 작성

**주 액터:** 운영 담당자  
**목표:** 처리 진행 또는 내부 협업 내용을 신고와 연결해 기록한다.  
**사전 조건:** 운영 권한이 있고 대상 신고가 존재한다.

**기본 흐름**
1. 담당자가 신고 상세에서 업데이트 작성을 선택한다.
2. 공개 업데이트 또는 내부 메모 범위를 선택한다.
3. 내용을 작성하고 저장한다.
4. 시스템은 작성자·시각·공개 범위를 기록한다.
5. 공개 업데이트는 신고자 화면에서 표시하고, 내부 메모는 운영 권한자에게만 표시한다.

**대안 흐름**
- 공개 업데이트 대신 내부 메모를 기록할 수 있다.
- 완료 처리에 필요한 결과 요약은 UC-007에서 기록한다.

**예외 흐름**
- 내용이 없거나 저장에 실패하면 기록을 생성하지 않고 재시도를 안내한다.
- 신고자는 내부 메모를 조회하거나 작성할 수 없다.

**사후 조건:** 조치 기록이 신고와 연결되고 지정한 공개 범위가 유지된다.  
**관련 규칙:** BP-PRIV-001, BP-AUTH-003  
**화면 참조:** 신고 상세·조치 이력  
**관련 요구사항:** FR-008, FR-010; NFR-002, NFR-003

### 5.7 UC-007: 상태 변경 및 완료

**주 액터:** 운영 담당자  
**목표:** 신고를 접수에서 조치 중으로 진행하고 결과를 기록해 완료한다.  
**사전 조건:** 운영 권한이 있고 신고가 미완료 상태다.

**기본 흐름**
1. 담당자가 최신 신고 상태를 확인한다.
2. 접수 건을 조치 중으로 바꾸고 필요한 조치 기록을 입력한다.
3. 해결 시 결과 요약을 입력하고 완료를 선택한다.
4. 시스템은 결과 요약 존재 여부와 현재 상태를 검증한다.
5. 상태 변경과 감사 이력을 한 트랜잭션으로 저장한다.
6. 완료 시 완료 시각을 기록하고 신고자에게 공개 가능한 결과를 표시한다.

**대안 흐름**
- 완료 이후 추가 대응이 필요하면 UC-002에 따라 후속 신고를 만들고 원 신고와 연결한다.
- 관리자는 완료 건을 수정할 수 있으며 수정 사유와 변경 이력을 남긴다.

**예외 흐름**
- 완료 요약이 없으면 완료를 거부하고 입력을 요청한다.
- 동시 변경으로 현재 상태가 달라졌으면 덮어쓰지 않고 최신 상태를 표시한다.
- 이력 저장 오류 시 상태 변경도 롤백한다.

**사후 조건:** 성공 시 새 상태와 감사 이력이 함께 저장되고, 완료 상태에는 결과 요약과 완료 시각이 있다.  
**관련 규칙:** BP-OPS-002, BP-ERR-002, BP-AUDIT-001  
**화면 참조:** 신고 상세·상태 변경  
**관련 요구사항:** FR-009, FR-010; NFR-003, NFR-004

### 5.8 UC-008: 자산 기준 관리

**주 액터:** 관리자  
**목표:** 신고에서 선택할 시설·전산 자산을 최신 상태로 관리한다.  
**사전 조건:** 관리자 권한으로 인증되어 있다.

**기본 흐름**
1. 관리자가 자산 관리 화면을 연다.
2. 자산명/관리번호, 유형, 위치를 등록하거나 기존 값을 수정한다.
3. 더 이상 신규 신고에 쓰지 않는 자산은 삭제 대신 비활성화한다.
4. 시스템은 변경자와 변경 시각을 기록한다.
5. 신고 이력의 자산 참조는 유지한다.

**대안 흐름:** 잘못 등록된 자산을 수정하고 변경 사유를 기록할 수 있다.  
**예외 흐름:** 중복 관리번호 등 유효성 충돌은 저장을 거부하고 항목을 안내한다.  
**사후 조건:** 활성 상태와 신고 선택 가능 여부가 갱신된다.  
**관련 규칙:** BP-INC-001, BP-AUDIT-001  
**화면 참조:** 자산 관리  
**관련 요구사항:** FR-003; NFR-001, NFR-003

### 5.9 UC-009: 사용자 역할·운영 기준 관리

**주 액터:** 관리자  
**목표:** 운영 권한과 미결정 상태인 운영 기준을 관리한다.  
**사전 조건:** 관리자 권한으로 인증되어 있다.

**기본 흐름**
1. 관리자가 사용자 또는 운영 기준 관리 화면을 연다.
2. 역할을 신고자·운영 담당자·관리자 중 하나로 지정하거나 변경한다.
3. 임박 기준 등 시스템이 지원하는 운영 기준을 입력한다.
4. 시스템은 변경 권한과 입력 범위를 검증하고 변경 이력을 기록한다.

**대안 흐름**
- 기관에서 기준을 확정하지 않은 값은 초기 제안값과 실제 확정값을 구분해 표시한다.
- 계정 초대·비활성 기능은 기관 인증 운영 방식 확정 후 구현한다.

**예외 흐름:** 권한이 없거나 기준값이 유효하지 않으면 변경을 거부한다.  
**사후 조건:** 새 역할·기준이 이후 요청과 집계에 적용된다.  
**관련 규칙:** BP-AUTH-002, BP-SLA-002  
**화면 참조:** 사용자·운영 기준 관리  
**관련 요구사항:** FR-002, FR-011; NFR-001

### 5.10 UC-010: 첨부·분석·내보내기 (P1)

**주 액터:** 운영 담당자, 관리자  
**목표:** 파일과 집계 자료를 제한된 권한으로 활용한다.  
**사전 조건:** P1 범위가 승인되고 파일·보존·내보내기 정책이 결정되어 있다.

**기본 흐름**
1. 권한 있는 사용자가 신고에 파일을 첨부하거나 기간별 집계를 조회한다.
2. 시스템은 파일 접근 권한과 현재 검색·필터 조건을 확인한다.
3. 내보내기 요청 시 조건을 적용한 CSV를 생성한다.
4. 결과와 오류를 화면에 안내한다.

**예외 흐름:** 권한 없음, 허용하지 않은 파일 또는 정책 미설정이면 요청을 거부한다.  
**사후 조건:** 승인된 권한 범위의 자료만 반환된다.  
**관련 규칙:** BP-AUTH-002, BP-DATA-001  
**화면 참조:** 신고 상세 첨부, 분석 화면  
**관련 요구사항:** FR-012; NFR-001, NFR-002

## 부록: 비즈니스 규칙 참조

- **BP-AUTH-001/002:** 인증 필수, 역할 기반 데이터·행동 분리.
- **BP-INC-001/002:** 표준 신고 필드, 유사 신고 안내 후 접수 허용.
- **BP-OPS-001/002:** 담당자·기한·상태 및 완료 결과 규칙.
- **BP-SLA-001/002:** 기한 지정과 임박·초과 계산. 실제 기준은 기관 확정 필요.
- **BP-AUDIT-001:** 주요 변경 이력의 책임 추적.
- **BP-PRIV-001 / BP-AUTH-003:** 공개 처리 요약과 내부 메모의 열람 범위 분리.
- **BP-ERR-001/002:** 실패 시 성공으로 오인시키지 않고 동시 변경·이력 실패를 일관되게 처리.
