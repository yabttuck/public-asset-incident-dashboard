## 1. 목적과 범위

RTM은 요구사항이 정책·사용자 흐름·검증 항목으로 연결되는지 확인하기 위한 표다. 요구사항 정의는 SRS를 기준으로 하며, 기관 정책 확정 전인 항목은 미결정으로 유지한다. 테스트 케이스 ID는 구현 단계에서 상세 시나리오로 구체화할 예정이다.

## 2. 상태 정의

- **정의됨:** SRS에 요구사항이 명시됨.
- **추적됨:** 정책·유스케이스·검증 기준과 연결됨.
- **계획:** 구현 및 실행 결과가 아직 없음.
- **미결정:** 기관 정책 또는 기술 선택이 필요함.

현재 요구사항 상태는 문서화 기준이며 구현 완료를 의미하지 않는다.

## 6. 미매핑 및 미결정 항목

현재 요구사항 중 정책 또는 검증 경로가 없는 항목은 없다. 다음 항목은 추적 연결은 되어 있으나 기관·구현 결정이 필요하다.

| 항목 | 영향 요구사항 | 결정 주체 / 시점 |
|---|---|---|
| SLA 시간·임박 기준 | FR-011 | 운영기관 / 파일럿 전 |
| 사용자 계정 발급 방식 | FR-001, FR-002 | 기관 관리자 / 인증 구현 전 |
| 우선순위·유형 값 | FR-007, FR-012 | 운영 책임자 / 분류 UI 확정 전 |
| 보존·백업·첨부 제약 | FR-008, FR-012, NFR-002 | 기관 개인정보·기록 담당 / 운영 전 |
| 브라우저·성능·가용성 목표 | NFR-006, NFR-007 | 서비스 책임자 / 배포 전 |

## 7. 갱신 절차와 영향 분석

요구사항이나 운영 정책이 바뀌면 PRD/정책서에서 근거를 확인한 뒤 SRS ID를 추가·수정하고, 연결된 유스케이스 및 검증 항목을 같은 변경에서 갱신한다. 변경 검토 시 다음을 확인한다.

1. 역할별 허용 행위와 RLS 영향
2. 상태·기한 계산 및 대시보드 집계 영향
3. 감사 이력과 데이터 모델 영향
4. 모바일·오류·빈 상태 화면 영향
5. P0/P1 범위와 미결정 정책의 변경 여부

- 요구사항: SRS의 FR-001, NFR-001 형식

- 검증 시나리오: TC-영역-번호 형식
- 정책: 비즈니스 정책서의 BP-* ID
