|---|---|

현재 앱과 운영 환경은 구성되지 않았다. 담당 조직·연락망·기관 SLA 확정 후 갱신하며, 본 문서는 운영 승인본이 아니다.

## 1. 유지보수 유형

| 유형 | 예시 | 처리 원칙 |
|---|---|---|
| 수정 | 신고 저장·권한·SLA 계산 오류 | 재현 단계와 영향 요구사항을 기록하고 회귀 검증 |
| 적응 | 기관 인증·브라우저·인프라 변경 | 권한·데이터·운영 영향 분석 후 반영 |
| 개선 | 검색·대시보드·접근성 개선 | 사용자 문제와 우선순위 근거 기록 |
| 예방 | 의존성 갱신, RLS 점검, 복구 연습 | 검증 환경에서 확인하고 승인된 배포 절차 적용 |

유형별 비율 목표는 운영 자료가 없어 설정하지 않는다.

## 2. 변경 요청 프로세스

~~~mermaid
flowchart LR
 A[요청 등록] --> B[영향·위험 분석]
 B --> C{승인}
 C -->|승인| D[구현·검토·테스트]
 C -->|보류/반려| E[사유 기록]
 D --> F[배포·운영 확인]
 F --> G[문서와 RTM 갱신]
~~~

### 변경 요청서 양식
- CR ID, 제목, 요청자, 요청일
- 문제/목표, 근거, 영향 사용자 및 요구사항 ID
- 제안 변경과 대안, 우선순위
- 보안·개인정보·RLS·데이터 영향
- 마이그레이션·테스트·롤백 계획
- 승인자·결정일·상태·관련 PR/이슈

### 영향 분석 및 승인
PRD·SRS·RTM, DB/API/화면/상세 설계, 권한·감사 이력, 대시보드 집계, 테스트 및 운영 가이드 영향을 검토한다. CR 승인 후 관련 문서를 함께 갱신한다. 업무 필요성, 개인정보 최소화, 권한 경계, 데이터 무결성, 복구 가능성, 테스트 가능성을 확인한다. 권한 우회·정보 노출·감사 이력 손실 우려가 해소되지 않으면 운영 반영을 보류한다.

## 3. 운영 SLA 및 에스컬레이션

장애 등급별 최초 응답·복구 시간, 가용성 목표, 지원 시간과 에스컬레이션 경로는 기관 정책이 없어 미정이다. 화면의 신고별 처리기한과 유지보수 지원 SLA는 서로 다른 개념이다.

운영 전 기관이 등급 기준, 등급별 응답/복구 목표, 당직·담당자, 보안·개인정보 연락 경로, 운영 시간, 위반 보고 방식과 측정 기준을 승인한다. 기준 승인 전에는 SLA 달성/위반을 판정하지 않는다.

## 4. 기술 부채 관리

| 분류 | 예 |
|---|---|
| 보안 | RLS 공백, 비밀값 관리, 의존성 취약점 |
| 데이터 | 보존 기준, 감사 이력 또는 인덱스 한계 |
| 품질 | 자동화 테스트·상태 흐름 검증 부족 |
| 운영 | 백업·복구 미검증, 지표 부재 |
| 접근성 | 키보드, 대비, 모바일 개선 |

기술 부채 항목에는 TD ID, 발견일, 설명·근거, 영향 요구사항, 위험/우선순위, 담당자·목표일, 해소 방법, 검증 결과를 기록한다. 보안·개인정보·데이터 무결성 위험은 편의성 개선보다 먼저 검토한다. 해소 후 회귀 검증과 문서를 갱신한다.

## 5. 운영 인수인계

인수 시 실제 시스템 구성도, 환경별 배포·복구 절차, 권한 담당자, 모니터링 주소와 경보 기준, 백업 주기·복구 검증, 정기 작업, 알려진 이슈, 긴급 연락망을 제한된 운영 문서에서 전달한다.

| 인수 항목 | 현재 상태 |
|---|---|
| 환경·접근 담당자 | 미작성 — 배포 환경 미구성 |
| 계정·권한 및 회수 절차 | 미정 — 기관 계정 정책 필요 |
| 정기 점검·백업/복구 | 미정 — 운영 구성 필요 |
| 알려진 이슈 | [테스트 결과 보고서](../05-테스트/테스트결과보고서.md) 참고 |
| 긴급 연락망·온콜 | 미정 — 운영 조직 지정 필요 |

비밀번호, 토큰, 서비스 역할 키는 이 문서나 Git에 기록하지 않고 승인된 비밀 관리 도구로 전달한다. 개인정보가 포함된 운영 자료를 개인 기기에 저장하지 않는다.

## 부록: 유지보수 보고 양식
기간·작성자·대상 버전, 처리 CR/결함/기술 부채 ID, 영향 요구사항, 검증 및 배포 증빙, 잔여 위험·다음 조치, 승인자·일시를 기록한다.
