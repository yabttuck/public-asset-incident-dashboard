# 화면(UI/UX) 설계서

## 1. 설계 원칙
[DESIGN.md](../../DESIGN.md)의 정보 위계와 토큰을 따른다. 대응 필요 신고, SLA 위험, 운영 추이, 상세 이력 순으로 시선을 유도한다. 상태는 색상과 텍스트로 함께 표시한다. 키보드 접근, 명확한 포커스, 반응형 화면을 제공한다. 화면의 버튼 숨김은 인가를 대체하지 않는다.

## 3. 전체 페이지 IA

아래 구조에서 `공통`은 로그인한 모든 역할이 사용하는 페이지, 역할별 메뉴는 인가된 사용자에게만 노출한다. 신고 상세는 역할에 따라 공개 정보와 운영 전용 정보가 달라진다.

~~~mermaid
flowchart TD
  LOGIN[로그인]
  LOGIN -->|신고자| MY[내 신고]
  LOGIN -->|운영 담당자·관리자| DASH[운영 대시보드]

  subgraph REPORTER[신고자 영역]
    MY --> NEW[신고 작성]
    NEW --> DUP{유사 신고 확인}
    DUP -->|계속 접수| CREATED[접수 완료 · 접수 번호]
    CREATED --> DETAIL_R[신고 상세 · 공개 정보]
    MY --> DETAIL_R
  end

  subgraph OPERATIONS[운영 담당자 영역]
    DASH --> QUEUE[운영 신고 목록]
    QUEUE --> DETAIL_O[신고 상세 · 운영 정보]
    DASH --> DETAIL_O
    DETAIL_O --> WORK[처리 패널]
    WORK -->|상태·담당·기한·조치 기록| DETAIL_O
  end

  subgraph ADMIN[관리자 영역]
    DASH --> ASSETS[자산 관리]
    DASH --> USERS[사용자·기준 관리]
  end

  DASH -. P1 .-> ANALYTICS[분석·내보내기]
~~~

### 3.1 내비게이션 구조

| 영역 | 페이지 | 페이지에서 이어지는 주요 동선 |
|---|---|---|
| 공통 진입 | 로그인 | 역할에 맞는 시작 화면으로 이동 |
| 신고자 | 내 신고 | 신고 상세 확인, 새 신고 작성 |
| 신고자 | 신고 작성 | 유사 신고 확인 → 접수 완료 → 신고 상세 |
| 운영 | 운영 대시보드 | 운영 신고 목록, 신고 상세, 관리자 기능 |
| 운영 | 운영 신고 목록 | 조건 검색·필터 → 신고 상세 |
| 운영 | 신고 상세·처리 패널 | 배정·기한·상태·조치 기록 → 최신 상세 확인 |
| 관리자 | 자산 관리 | 자산 등록·수정·비활성화 |
| 관리자 | 사용자·기준 관리 | 역할 및 운영 기준 관리 |
| 운영 (P1) | 분석·내보내기 | 기간·유형·처리시간·SLA 분석 및 CSV |

### 3.2 접근 원칙

- 로그인 후 신고자는 `내 신고`, 운영 담당자와 관리자는 `운영 대시보드`를 기본 화면으로 본다.
- 신고자와 운영자는 같은 신고 상세의 서로 다른 정보 범위를 본다. 내부 메모와 감사 정보는 운영 권한에 한정한다.
- 사용자·기준 관리와 자산 관리는 관리자 전용이다. 메뉴 노출과 별개로 서버 및 데이터베이스에서도 권한을 검사한다.
- 분석·내보내기는 P1 페이지로, 첫 MVP 디자인에서는 후순위로 둔다.

## 5. 공통 상태와 반응형
- 데이터 화면은 로딩, 오류, 데이터 없음, 필터 결과 없음 상태를 각각 제공한다.
- 실패 시 성공으로 표시하지 않고 입력값을 보존하며 재시도 경로를 안내한다.
- 모바일은 표를 핵심 요약 카드나 적응형 목록으로 표시한다.
- 운영 데스크톱은 사이드바와 상세 데이터 표를 사용한다.
- 날짜는 한국 표준시로 표시하며 기한 없음은 임박/초과와 구별한다.
- 키보드 포커스, 라벨 연결, 명확한 오류 텍스트를 제공한다.

## 6. 화면 상세
### 6.1 로그인
서비스명과 기관에서 확정한 인증 입력, 로그인 동작, 오류 안내를 배치한다. 공개 회원가입은 계정 발급 정책 미정으로 노출하지 않는다. 인증 성공 시 역할별 시작 화면으로 이동한다.

### 6.2 대시보드
상단에 제목과 기준 시각, 전체·미처리·임박·완료 요약 카드, 위험 신고, 최근 신고 표를 배치한다. 표에는 ID, 제목, 자산/위치, 우선순위, 상태, 담당자, 기한, 최근 변경을 포함한다. 완료 건은 미완료 SLA 초과 건수에서 제외한다.

### 6.3 신고 목록
검색, 상태·우선순위·자산/위치·기간 필터, 정렬, 결과 수, 필터 초기화 동작을 제공한다. 신고자는 본인 데이터만 보고 운영자는 전체 업무 범위를 본다. 필터는 권한 경계를 넓히지 않는다.

### 6.4 신고 작성
자산 선택 또는 위치, 제목, 증상, 우선순위, 발생 시각을 입력한다. 필수값 오류는 해당 필드에 표시한다. 미해결 유사 신고 안내 후 사용자가 계속 접수하거나 취소할 수 있다. 안내는 차단·자동 병합이 아니다. 저장 중 중복 제출을 막고 실패 시 입력값을 유지한다.

### 6.5 신고 상세 및 처리 패널
공통으로 접수 ID, 신고 정보, 상태, 공개 처리 이력을 표시한다. 운영 권한자는 배정, 우선순위, 기한, 내부 메모, 감사 이력도 확인한다. 내부 메모는 신고자 화면에 반환하지 않는다. 완료 시 결과 요약을 요구하며 후속 건이 필요하면 새 신고 연결을 안내한다. 동시 변경은 최신 데이터 재확인을 요청한다.

### 6.6 관리자 화면
자산은 등록·수정·비활성화할 수 있고 기존 신고 참조는 유지한다. 역할 변경은 관리자에게만 허용한다. 계정 초대·삭제 등 미결정 정책의 기능은 확정 전 제공하지 않는다.

### 6.7 분석·내보내기 (P1)
기간 추이, 유형별 건수, 평균 처리 시간, SLA 준수 현황을 제안한다. 통계 정의, 파일 정책, 내보내기 권한은 구현 전 확정한다.
