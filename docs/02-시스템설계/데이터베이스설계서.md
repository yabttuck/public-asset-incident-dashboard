# 데이터베이스 설계서

## 1. 개요
Supabase Postgres 기준의 데이터 모델 초안이다. 실제 마이그레이션 전에 기관의 분류, 보존, 개인정보 정책을 확인한다. 시각은 시간대 포함 형식으로 저장하고 화면에서는 한국 표준시로 표시한다. 업무 데이터 접근은 RLS 기본 거부 원칙으로 설계한다.

## 2. ER 다이어그램
~~~mermaid
erDiagram
~~~

## 3. 테이블 명세
### 3.1 profiles
| 컬럼 | 형식 | 규칙 |
|---|---|---|
| id | uuid PK, FK auth.users.id | 인증 ID |
| display_name | text | 필수 |
| role | user_role | reporter/operator/admin |
| is_active | boolean | 비활성 계정 제한 |
| created_at, updated_at | timestamptz | 시스템 시각 |

역할 변경은 관리자 권한의 서버 경로로 제한하며 자기 승격을 막는다.

### 3.2 assets
| 컬럼 | 형식 | 규칙 |
|---|---|---|
| id | uuid PK | 자산 ID |
| asset_name | text | 필수 |
| asset_number | text unique nullable | 기관 관리번호 |
| asset_type, location | text | 기관 분류와 위치 |
| is_active | boolean | 신규 신고 선택 여부 |
| created_by | uuid FK profiles | 등록자 |
| created_at, updated_at | timestamptz | 시스템 시각 |

삭제 대신 비활성화를 사용해 기존 신고 참조를 보존한다.

### 3.3 incidents
| 컬럼 | 형식 | 규칙 |
|---|---|---|
| id | uuid PK | 내부 ID |
| incident_number | text unique | 사용자 접수 번호 |
| reporter_id | uuid FK profiles | 필수 신고자 |
| asset_id | uuid FK assets nullable | 선택 자산 |
| location_snapshot | text | 자산 미선택 시 필수 원문 위치 |
| title, description | text | 필수 |
| priority | incident_priority | 단계는 기관 정책 미결정 |
| status | incident_status | received/in_progress/completed |
| assignee_id | uuid FK profiles nullable | 담당자 |
| occurred_at, created_at, updated_at | timestamptz | 발생·접수·수정 시각 |
| due_at, completed_at | timestamptz nullable | 처리 기한·완료 시각 |
| resolution_summary | text nullable | 완료 시 필수 |
| follow_up_of | uuid FK incidents nullable | 후속 신고 연결 |

완료 상태는 결과 요약과 완료 시각을 요구한다.

### 3.4 incident_updates
id, incident_id, author_id, visibility(public/internal), body, created_at을 저장한다. 신고자는 공개 항목만 조회한다. 수정·삭제 정책은 미결정이며 초기에는 추가 기록 방식이 적절하다.

### 3.5 incident_audit_logs
id, incident_id, actor_id, action, old_values, new_values, created_at을 저장한다. 상태·담당자·우선순위·기한 변경을 기록한다. 일반 사용자의 수정·삭제를 막고 업무 변경과 같은 트랜잭션에서 기록한다.

첨부는 P1이다. 승인되면 신고 ID, Storage 경로, 파일명, 크기, 업로더, 시각을 저장하는 메타데이터 테이블을 추가한다.

## 4. 도메인 값
| 도메인 | 값/정의 |
|---|---|
| user_role | reporter, operator, admin |
| incident_status | received, in_progress, completed |
| visibility | public, internal |
| priority/type | 기관 승인 후 값 확정 |
| SLA 임박 | 미완료, 기한 존재, 남은 시간이 설정 임계값 이하 |
| SLA 초과 | 미완료, 기한 존재, 현재 시각이 기한 경과 |

24시간은 제안 기본값일 뿐 확정 정책이 아니다.

## 5. 권한·무결성
- 비인증 요청은 거부한다.
- 신고자는 reporter_id가 본인인 신고와 공개 업데이트만 읽는다.
- 운영자는 업무 신고를 조회·처리하며 관리자는 사용자·자산·기준을 관리한다.
- 권한과 현재 상태를 DB 함수/RPC에서 재검증한다.
- 상태 변경 및 감사 로그는 단일 트랜잭션으로 성공/실패한다.
- 감사 로그는 일반 앱 역할의 UPDATE/DELETE를 거부한다.
- 자산 미선택 위치 신고 허용, 접수 ID 유일성, 완료 요약 필수 조건을 검증한다.

## 6. 인덱스 후보
- incidents(reporter_id, created_at desc): 내 신고
- incidents(status, due_at): 미완료 및 SLA 관제
- incidents(assignee_id, status, updated_at desc): 담당자 목록
- incidents(asset_id, status): 유사 신고 확인
- incident_updates(incident_id, created_at): 처리 타임라인
- incident_audit_logs(incident_id, created_at): 감사 조회

실제 쿼리와 데이터량을 확인해 최적화한다. 샤딩·파티셔닝은 현재 범위에서 제외한다.

## 7. 마이그레이션·백업
DDL과 RLS는 Supabase CLI 마이그레이션으로 버전 관리하고 코드 리뷰를 거친다. 스키마 변경 때 권한 테스트도 함께 갱신한다. 백업 주기, 보존 기간, 복구 목표는 요금제와 기관 기록 정책 확인 후 확정하며 운영 시작 전 복구 검증을 수행한다.
